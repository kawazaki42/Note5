# Внутренняя память процессора

Идеальная память должна обеспечивать АЛУ командами и операндами так,
чтобы не вызывать его простоев

Для этого схемы памяти должны обладать тем же быстродействием, что и
схемы АЛУ

<!-- дорожек -->
Кроме того, на скорость передачи сигналов влияет расстояние
передачи сигнала

Поэтому память должна быть расположена как можно ближе к АЛУ

Из-за технических и финансовых ограничений, сделать так
чтобы ОП удовлетворяла всем этим критериям, будет нерентабельно

Поэтому была разработана регистровая память,
состоящая из триггеров и обладающая максимально возможным быстродействием

Кроме того, эта память размещается прямо в кристалле процессора

При этом триггерная память требует большого количества дорогих транзисторов и занимает значительное место внутри процессора

Поэтому объем регистровой памяти сильно ограничен

Регистры обычно имеют размер равный разрядности АЛУ

Некоторые из них имеют в своем составе меньшие подрегистры и могут
объединяться в пары большей разрядности

По функциональному назначению регистры объединяются в группы

Чаще всего используются регистры общего назначения и регистр флагов

Со временем количество обменов с памятью неуклонно возрастало;
вычисления требовали одновременного хранения большего количества данных

Это привело к тому, что регистровой памяти стало недостаточно и АЛУ
пришлось простаивать

Оптимальным решением данной проблемы было введение между регистровой
и основной памятью дополнительной буферной памяти среднего обьема
и приемлемого быстродействия

Это называется кэш-память

Изначально кэш находился только внутри процессора

Потом его стало не хватать и разработчики стали размещать дополнительный
кэш вне процессора, создавая многоуровневую структуру

# Принцип работы кэш-памяти

Целесообразность и эффективность применения механизма кэширования
определяется следующими свойствами большинства программ:
- Некоторые группы команд повторяются много раз
- Наиболее вероятно последовательное выполнение команд, находящихся по близким адресам
  - Обычно это характерно и для данных (операндов)

Исходя из этого, идея кэширования заключается в сохранении в кэше
команд и данных, которые уже использовались процессором,
а также соседних элементов, расположенных по смежным адресам

Данный механизм позволяет обойтись без длительных обменов с основной
памятью с определенной вероятностью

<!-- Многоуровневые кэши еще  -->

Кэш работает под управлением своего контроллера.
Процессор ничего о нем не "знает", а просто выполняет обращение к основной памяти.

Контроллер кэша перехватывает эти обращения и определяет, откуда
будут загружаться данные.

Поскольку кэш не может хранить всю основную память,
существуют механизмы обновления информации в кэше, а также
соответствие кэша областям основной памяти

Для этого в кэше имеется специальная память, называемая каталогом
или памятью тегов.

В ней хранится список соответствия элементов кэша областям основной памяти

Адресуемые элементы памяти внутри кэша, имеющие последовательные адреса
называются блоком или строкой кэша

Все обмены с кэшем идут строго блоками, даже если адресуется один элемент

При обращении процессора к памяти, контроллер кэша проверяет, есть ли
запрашиваемая информация в кэше.
- Если да, происходит кэш-попадание
  - Данные передаются в процессор напрямую из кэша

<!-- - Если нет, происходит кэш-промах
  -  -->

В противном случае возникает кэш-промах.

При этом информация загружается в процессор из основной памяти
и одновременно сохраняется в кэш вместе с соседними данными.

Важной задачей является поддержание соответствия информации, одновременно
хранящейся в кэше и в основной памяти

Для этого существует два основных алгоритма:
- Сквозная запись
  - Основная память обновляется сразу же после обновления соответствующего кэша
  - Способ прост, но при нескольких обращениях к одним и тем же данным все равно придется взаимодействовать с ОП, что <!-- нивелирует --> отменяет преимущество кэша
- Обратная запись
  - Изменяемая информация хранится только в кэше
  - Содержимое основной памяти не будет изменяться до тех пор,
    пока данные не удалятся из кэша
  - Удаление данных из кэша происходит когда он полон и требуется
    записать новую порцию данных
  - Эффективность взаимодействия также может быть повышена введением флага модификаций 

Существуют разные механизмы удаления информации из кэша
- Удаление случайного блока
  - Самый простой
- Удаление блока, который дольше всего не использовался
  - Самый эффективный

# Функция отображения кэш-памяти

Она устанавливает соответствие между блоками кэша и блоками в ОП

Существует 3 таких функции:

- Прямое отображение
- Ассоциативное отображение
- Множественно-ассоциативное отображение

Данные функции предполагают, что основная память организована
по страничному принципу

В этом случае память представляется в виде книги

То есть состоит из страниц, каждая из которых содержит последовательность
строк

В каждой строке находится несколько элементов (_слов_)

В этом случае, чтобы найти нужное слово, необходимо знать 3 составляющие:
- Номер страницы
- Номер строки
- Смещение в строке

Это логический адрес слова

Функция прямого отображения требует, чтобы основная память
была разбита на страницы, размер которых равен объему кэша

При этом каждой i-й строке кэша соответствует только i-я строка
любой из страниц основной памяти

В каждый момент времени одна строка кэша может содержать копию строки
только одной страницы ОП

Поэтому такая кэш-память должна снабжаться специальным указателем,
содержащим номер страницы, хранящейся в кэше

Такие указатели называются _тегами_ и формируют _память тегов_

При прямом отображении количество ячеек тегов равно количеству
строк кэша

Когда процессор формирует обращение к основной памяти,
контроллер кэша:
- Перехватывает адрес
- Выделяет из него номер строки
- Затем по этому номеру обращается к памяти тегов
- И сравнивает тег с номером запрашиваемой страницы
- Если они равны, происходит кэш-попадание
  - Данные извлекаются из кэша
- Иначе - кэш-промах
  - Данные загружаются из ОП и дублируются в кэше

Обмены между кэшем и ОП происходят строками целиком

Технология прямого отображения достаточно проста, но имеет некоторые недостатки:
- Невозможно гибко перераспределять объем кэша
  - простой
- Если процессору поочередно требются данные, смещенные друг относительно друга на величину, кратную размеру страницы, будет происходить постоянное обновление одной строки
  - Кэш будет работать вхолостую (будет бесполезен)

# Ассоциативное отображение

Нужно для решения проблем прямого отображения

В i-й строке кэша может хранится любая строка любой страницы основной
памяти

Объем кэша в этом случае может отличаться от объема страницы основной памяти

Такой кэш эффективнее использует свое адресное пространство,
но усложняет процесс поиска информации:
- В тегах нужно хранить в два раза больше ячеек
  - номера и страниц и строк
- Чтобы найти нужную информацию, может потребоваться полный перебор памяти тегов
  - Перебор можно сделать параллельно, но это усложнит аппаратную структуру
